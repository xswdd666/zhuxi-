# 筑析 AI｜3 分钟演示台词与操作

准备：在项目根目录运行 `python -m uvicorn app.main:app --reload`，浏览器打开 <http://127.0.0.1:8000/>。为展示无 Key 降级，不创建 `.env` 或确保 `DEEPSEEK_API_KEY` 未设置。

## 0:00–0:30｜创建项目与上传

操作：填写“社区活动中心改造演示”，类型“改造”，点击“创建项目”。上传 `fixtures/demo-brief.txt` 和 `fixtures/site-context-illustration.png`。

台词：“这是本地单人 MVP。文本会拆成可定位来源，图片只保存为待人工观察资料；它不会被伪造成现场事实。”

核对：TXT 显示 `parsed`；图片显示“未启用 OCR/视觉模型，已保存待人工观察”。

## 0:30–1:15｜生成并确认洞察

操作：点击“生成带来源洞察”。检查页面提示“演示降级”或 `demo_fallback`，并展开卡片来源。

台词：“没有模型 Key 时仍能演示。每张文本卡都有文件、片段位置和原文摘录；图片卡被标成信息缺口，必须人工核实。”

操作：先尝试“生成问题卡”（按钮应不可用；也可用 API 验证得到 `GATE_BLOCKED`）。随后确认两张有来源的文本洞察，例如一张场地事实和一张设计约束。

台词：“确认是硬门禁。待确认、已修改或待验证的洞察都不会进入下游。”

## 1:15–2:10｜问题与策略

操作：点击“生成问题卡”，勾选一张 `ready` 问题卡，再点击“基于已选问题生成策略”。

台词：“问题卡关联已确认洞察；若证据不足，系统会明确标为 hypothesis 并写出待验证项，不把假设说成事实。”

操作：在策略卡中展示“前提”“取舍”“验证项”，勾选其中一条策略。

台词：“策略不是结论，它同时展示实施前提、代价和下一步验证动作。”

## 2:10–3:00｜导出与可追溯性

操作：点击“生成并下载 Markdown”，打开预览或下载文件。

台词：“导出只包含已确认洞察、对应问题和已选策略；未确认洞察与未选策略不会混入正式大纲。文件写入本地 `output/`，刷新或重启后 SQLite 中的项目与卡片仍可恢复。”

结束语：“今天交付的是可演示、可审阅、可追溯的闭环，不是专业规范审查或生产系统。”

## API 快速验收（可选）

`POST /api/projects/{project_id}/problems:generate`、`POST /api/projects/{project_id}/exports/markdown` 在没有已确认洞察时应返回 `GATE_BLOCKED`。选择策略后，`POST /api/projects/{project_id}/exports/markdown` 返回下载 ID，`GET /api/exports/{export_id}/download` 返回 Markdown。
